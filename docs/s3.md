# S3 对象存储

`store/object` 定义不依赖 AWS SDK 的 Reader、Writer、Lister、Presigner 和组合 Store；`store/s3` 使用 AWS SDK v2 实现。业务可依赖自己需要的小接口。

支持 Put（自动分片）、Get（流式 body / byte range / version）、Head、Delete、ListObjectsV2 分页和 GET/PUT 预签名 URL。底层使用 AWS 当前推荐的 [transfer manager](https://github.com/aws/aws-sdk-go-v2/discussions/3306)。endpoint 接入方式遵循 [AWS SDK v2 endpoint 配置](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-endpoints.html)。

## 配置

```toml
[storage.s3]
enabled = true
bucket = "my-files"
region = "ap-southeast-1"
# AWS S3 不需要 endpoint；兼容服务按实际部署设置：
# endpoint = "http://127.0.0.1:9000"
# usePathStyle = true

requestTimeout = "2m"
healthTimeout = "3s"
checkBucket = true
partSizeBytes = 8388608
uploadConcurrency = 2
maxConcurrentUploads = 4
presignExpiry = "15m"
maxAttempts = 3
```

环境变量前缀跟随 `config.Source.EnvPrefix`，默认支持：

| 环境变量 | 配置 |
|---|---|
| `GOSVC_S3_BUCKET` | 设置 bucket 并启用连接器 |
| `GOSVC_S3_REGION` | region；未指定时由 AWS 配置解析，最终回退 us-east-1 |
| `GOSVC_S3_ENDPOINT` | 自定义 http(s) origin，不接受嵌入凭据、路径或 query |
| `GOSVC_S3_USE_PATH_STYLE` | true / false |
| `GOSVC_S3_ACCESS_KEY_ID` | 显式 access key ID |
| `GOSVC_S3_SECRET_ACCESS_KEY` | 显式 secret access key |
| `GOSVC_S3_SESSION_TOKEN` | 可选临时凭据 token |

显式 key ID / secret 必须同时设置。未设置时使用 [AWS 标准凭据链](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-gosdk.html)，支持 AWS 环境变量、共享配置与角色等来源；凭据刷新由 SDK 管理。admin 配置快照会遮蔽三项凭据。

`checkBucket=true` 会在创建、热更新和 readiness 检查时调用 HeadBucket。该检查需要 bucket 级权限；只授予对象读写权限时可显式设为 false，此时该依赖探针报告 skipped。框架不会替应用创建 bucket、修改权限或配置生命周期策略。

## 业务代码

```go
objects := app.Objects() // 可长期持有，跟随重载；未启用时操作返回 object.ErrDisabled

result, err := objects.Put(ctx, "reports/2026-10.txt", reader, object.PutOptions{
    ContentType: "text/plain; charset=utf-8",
    Metadata: map[string]string{"source": "report-service"},
})
```

```go
download, err := objects.Get(ctx, "reports/2026-10.txt", object.GetOptions{})
if err != nil { return err }
defer download.Body.Close()
_, err = io.Copy(destination, download.Body)
return err
```

包路径分别为 `github.com/Tokimorphling/gosvc/store/object` 和 `github.com/Tokimorphling/gosvc/store/s3`。
独立使用连接器时，从 `config.Default().Storage.S3` 获取完整默认配置，设置 bucket 等字段后调用 `s3.New(ctx, cfg)`，最后关闭客户端。可运行的 CLI 见 [examples/s3](../examples/s3/README.md)。

## 传输与生命周期

- 上传接受 `io.Reader`，不将完整大文件读入内存。transfer manager 按分片大小缓冲，`uploadConcurrency` 限制单次上传的分片并发，`maxConcurrentUploads` 限制每个客户端同时缓冲的上传数。小文件会缓冲到阈值以内，文件输入仍有分片缓冲开销。
- `PutOptions.Size` 可提供已知长度；未知长度保持 nil。输入 reader 由调用方负责关闭；阻塞的自定义 reader 也必须自行响应取消，Go 无法强制打断任意 Read。
- 上传失败或取消会尝试 AbortMultipartUpload，清理使用独立的 `healthTimeout` 预算。网络故障也可能导致 abort 失败，生产 bucket 可配置清理未完成分片的生命周期规则。
- `requestTimeout` 覆盖排队、重试、上传，以及下载 body 的整个消费期。大文件应配置足够预算；调用方更短的 context deadline 仍优先。
- Get 返回后不会立即取消请求。EOF、Close、取消或 deadline 都会关闭响应体、结束观测并释放资源；始终显式关闭 body。
- `app.Objects()` 在普通操作期间持有当前存储代际的 lease，Get 延长至流结束。新客户端通过检查后再发布；旧下载仍能完成，失败的重载保留旧连接和有效配置。热更新同时存在两代客户端时，各自的上传上限独立生效。
- Get 是单条顺序 HTTP 流，不会预先并行下载整个对象。List 只返回一页，调用方用 NextToken 继续，避免一次收集全部对象。

## 错误、观测与预签名

底层错误保留在 error chain 中，并映射为 `apierror` 的 not_found、permission_denied、unauthenticated、invalid_argument、conflict、rate_limited 或 unavailable。取消和超时仍可通过 `errors.Is` 判断。Delete 遵循 S3 的幂等语义；它不承诺对象此前存在，版本化 bucket 的删除行为由 S3 规则决定。

运行时自动记录 `gosvc_object_requests_total{operation,outcome}` 与 `gosvc_object_request_duration_seconds{operation}`，并在启用追踪时创建 client span。Get 的耗时包含 body 消费；指标不使用对象 key、URL 或密钥作为 label。独立客户端可用 `WithObserver` / `WithTracer` 接入观测。

预签名有效期为 1 秒至 7 天；传 0 使用 `presignExpiry`。临时凭据可能更早过期。调用方必须使用返回的 Method 和 Headers，尤其是预签名上传的 metadata/header 约束。签名不会检查对象是否存在，也不保证 bucket 权限正确；生成后的 URL 不会因客户端重载而自动撤销。

自定义 endpoint 默认仅计算协议要求的请求 checksum，以减少可选 aws-chunked 扩展对兼容端点的要求；不关闭 TLS 验证。兼容服务需支持对应的 S3 API 和 SigV4，实际能力仍以该服务为准。

## 验证范围

自动测试使用本地 HTTP S3 协议桩，经真实 AWS SDK 发请求，覆盖请求签名存在性、特殊字符 key、CRUD/metadata/range、分页、预签名请求、分片成功与 abort、错误映射、下载生命周期、配置脱敏、readiness 和热切换。
本地协议桩不验证完整 SigV4 密码学，也不替代真实 AWS/兼容服务验收；这些测试不需要云凭据，不会访问真实 bucket。
